# 0008 隱私與合規
- 狀態：已採納（部分待律師確認）（2026-10-26）｜關聯：#1、#15
## 背景
上架 Google Play 前要先定最低年齡、刪除帳號、資料存放地，以及定位、分析與 Google 地圖資料能存多久。上架檢查清單見 [Issue #15](https://github.com/77KiD/-APP/issues/15)。
## 決策
1. 註冊時填生日。未滿 13 歲不能註冊，以避開美國 COPPA 的家長同意規定。已能註冊的人，是否未成年仍一律以 18 歲判斷（刻意簡化，見 0007）。是否需監護人同意待律師確認。
2. App 內可刪除帳號（Google Play 要求），由 Cloud Function 處理。個人資料、位置、生日、回憶錄，以及修改紀錄中的個人內容直接刪除。其他人的行程不能壞掉，原本由他修改處顯示「已刪除的成員」。
3. Firestore 放在 `asia-east1`（台灣）。地區建立後不能更改；日後分流需另建資料庫並搬資料。
4. Firebase Analytics 與 Crashlytics 預設關閉，使用者同意後才啟用。原生 App 不用 cookie。位置權限請求前先顯示用途說明，而且只在按「發送定位」時取得。位置與生日為敏感個資，其他成員只看得到是否未成年。
5. Google Maps：`place_id` 可長期保存。來自 Places、Directions、Routes 等服務的座標最多快取 30 個連續日曆日，到期必須刪除。行程裡的景點名稱、順序、時間、`place_id` 與座標是自己的資料，可離線保存（座標仍受 30 天限制）。路線線條、交通時間與底圖不長期快取。離線時顯示行程清單，並在簡易地圖上把景點連成直線表示大概方向，提示「連線後更新路線」。導航與回程交通連網時即時查詢。日後若需完整離線地圖，可考慮 OpenStreetMap 離線圖資。設定 Maps API 用量上限與預算警示。
6. 不適用：cookie 政策（除非日後有網站）、退款政策（除非有付費功能）。
## 理由
13 歲門檻對齊 COPPA 對兒童線上服務的家長同意義務，避免先做監護流程。帳號刪除若連別人的行程一起清掉，團體資料會壞。分析預設關閉，才不會在同意前送出資料。座標期限依現行 Google 條款，而不是自行延長。
## 條款核對
2026-10-26 對照現行條款，30 天與 `place_id` 的寫法成立：

- [Google Maps Platform Terms of Service](https://cloud.google.com/maps-platform/terms) 3.2.3(b)：除服務特定條款明文允許外，不得快取 Google Maps Content。3.2.3(e)：不得把 Google 地圖核心服務與非 Google 地圖併用（例如把 Places 內容畫在非 Google 地圖上）。
- [Maps Service Specific Terms](https://cloud.google.com/maps-platform/terms/maps-service-terms) 第 3 節：可快取允許快取的 Google ID，例如 Places、Directions、Geolocation、Routes 的 `place_id`。Places API 14.3、Directions API 4.3、Routes API 19.3、Geocoding API 6.3.1：緯經度最多快取 30 個連續日曆日，之後必須刪除。Distance Matrix API 第 5 節沒有快取例外，交通時間不寫進離線快取。
- [Place IDs](https://developers.google.com/maps/documentation/places/web-service/place-id)：`place_id` 不受一般快取限制，可事後再用；Google 建議超過 12 個月就刷新。本決策先長期保存，刷新排程留到實作。
- Geocoding API 6.3.2 另允許在「只服務發起該次請求的使用者、不取代再次呼叫、不跨使用者共用」時無限期保存緯經度。本決策不採用這條約外，座標一律最多 30 天。

## 後果／取捨
監護人同意仍待律師，18 歲與各地成年年齡可能不同。超過 30 天的座標要刪，離線直線只畫還在期限內的點。簡易地圖不是 Google 地圖，若被認定為把 Places 座標畫在非 Google 地圖上，可能觸及 3.2.3(e)；上架前要再對一次。`asia-east1` 選定後不能改地區，分流要搬家。刪除帳號後，修改紀錄裡該成員的個人內容消失，只留「已刪除的成員」。
