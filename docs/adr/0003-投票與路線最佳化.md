# 0003 行程規劃：投票選景點 + 後端排路線
- 狀態：已採納（部分待定）（2026-10-26）｜關聯：#1
## 背景
團體自由行最常卡在意見不合、行程排不出來。
## 決策
1. 成員提議景點並投票，資料存 Firestore 即時同步；達門檻的景點成為「候選景點」。門檻：**待定**（暫列「例如過半」）。
2. 由 Cloud Function 以蜂群類最佳化演算法（蟻群／人工蜂群）排每日路線，輸入為候選景點、交通時間（Distance Matrix）、營業時間、每日可用時數；結果寫回 Firestore，成員可手動微調。
3. 候選景點排不下時的處理（自動刪除或先詢問全團）：**待定**。
## 理由
在後端執行可保護付費 API 金鑰、方便調整演算法；每日景點通常少於 15 個，運算數秒內完成。
## 後果／取捨
排路線需要網路；演算法結果非唯一，測試以規則驗證（不違反營業時間、不超過每日時數）。
