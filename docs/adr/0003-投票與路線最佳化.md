# 0003 行程規劃：投票選景點 + 後端排路線
- 狀態：已採納（2026-10-26）｜關聯：#1
## 背景
團體自由行最常卡在意見不合、行程排不出來。
## 決策
1. 成員提議景點並投票，資料存 Firestore 即時同步。每位成員對每個景點投一票：想去（+1）、沒意見（0）、不想去（-1）。總分 > 0 才進入「候選景點」。投「不想去」的人數超過全團成員人數 1/4 的景點直接排除（不論幾人投票）；「超過」指嚴格大於。例：4 人團需 2 票、8 人團需 3 票才排除。
2. 由 Cloud Function 以蜂群類最佳化演算法（蟻群／人工蜂群）排每日路線。演算法依分數每天最多排 5 個景點，並考慮交通時間（Distance Matrix）、營業時間、每日可用時數；結果寫回 Firestore，成員可手動微調。同分時先比「想去」票數多者，再比「不想去」票數少者。
3. 排不下的景點放入「備選清單」，由成員決定換上或刪除，演算法不自動刪除。
## 理由
在後端執行可保護付費 API 金鑰、方便調整演算法；每日景點通常少於 15 個，運算數秒內完成。
## 後果／取捨
排路線需要網路；演算法結果非唯一，測試以規則驗證（不違反營業時間、不超過每日時數、每天最多 5 個景點）。
