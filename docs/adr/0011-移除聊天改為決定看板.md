# 0011 移除聊天，改為決定看板與分享到 LINE
- 狀態：提議（2026-11-04）｜取代：0009 第 4–10 點（群組聊天、檢舉封鎖、保存期限、備份、刪除帳號例外、自訂狀態、檢舉處理）｜關聯：0009、0003、0007、0008
## 背景
痛點清單 P03：台灣的揪團聊天幾乎都在 LINE，App 內聊天會跟 LINE 正面競爭而且必輸。情境裡 App 聊天室 2 則、LINE 群組 147 則，大家出發前一晚還是在 LINE 往上滑找飯店地址。使用者要的是「整理好的結論」，不是另一個聊天室。概念 UI 缺點分析第 1 點也指出：同時有探索、投票、排程、找人、聊天、待辦、分帳、叫車，第一次使用的人看不出產品主要在解決什麼。

聊天也是 0009 裡成本最高的一塊：Realtime Database、Cloud Storage、FCM、檢舉 24 小時處理、6 個月保存與刪除排程、刪除帳號的例外，以及 Google Play 的使用者生成內容政策。
## 決策
1. **不做 App 內聊天。** 底部導覽移除「聊天」分頁，不建立 `trips/{tripId}/messages`、`trips/{tripId}/chat/` 圖片路徑與相關規則。0009 第 4–10 點作廢。
2. **首頁改成決定看板**，分三區：
   - **已決定**：日期、住宿、航班、已定案的行程版本（0010）等。
   - **待決定**：投票中、修改申請待審、尚未成團。
   - **我的待辦**：只列「我」現在要做的少數事項（概念 UI 缺點分析第 3 點）。
   區塊順序依旅程階段調整（規劃中、出發前、旅途中、旅程結束），同一個首頁，不做四套介面。
3. **一鍵分享到 LINE**：邀請、投票、待辦、決定結果都能用 Android 分享選單送出一段文字＋連結。第一版只用系統分享（`Intent.ACTION_SEND`），不串 LINE 官方 SDK，也不做 LINE 機器人。
4. **保留 0009 第 1–3 點**：即時同步、連線狀態橫幅、成員在線狀態不受影響。
5. 走散時的聯絡改由「找人」（0002 按需位置分享）與之後的集合卡回應（路線圖 v1.2）承擔，不靠聊天。
## 理由
決策與分工才是競品（Funliday、Wanderlog、LINE 記事本）沒做好的地方。拿掉聊天後，少掉兩項 Firebase 服務、一條排程刪除、一個內容審核責任與一個刪除帳號的隱私例外，資源可以放到決定看板與任務認領。
## 後果／取捨
- 隊員之間的討論完全回到 LINE；App 只承接「結論」與「誰要做什麼」。
- 決定看板與分享文字要寫得能獨立閱讀，因為很多人只會在 LINE 看到它。
- 0008、#15 的資料清單要移除聊天訊息、在線狀態以外的聊天相關項目。
- 若之後要做 LINE 機器人，另開 ADR；本 ADR 不承諾。
