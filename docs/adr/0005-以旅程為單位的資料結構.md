# 0005 資料結構以「旅程」為單位
- 狀態：已採納（2026-10-26）｜關聯：#1
## 背景
回憶錄放第二階段，但不希望屆時搬資料或改結構。
## 決策
以「旅程（Trip）」為根，成員、景點、投票、行程、成員位置與第二階段的打卡都掛在旅程底下。第二階段回憶錄（私人版與團體版；自己打卡或手動「存成回憶」；依行程觸發提醒，不用背景定位）直接讀取既有資料。

旅程有選填欄位「預計回程時間」。使用者填大概的時間即可，旅途中隨時可以修改（飛機誤點也是旅途回憶）。旅程在最後一次填寫的預計回程時間自動結束並清除所有成員位置；沒填就在結束日當天 23:59（旅程當地時區）結束。建立者可以提早手動結束。

行程另有修改紀錄（例如 `trips/{tripId}/itineraryHistory` 子集合），保存被覆蓋的版本，可以查看與還原。
## 理由
權限、清除與匯出都能以旅程為邊界處理。有預計回程時間後，找人地圖的位置清除不必靠人工記得按結束；旅途中改過的時間以最後一次填寫為準。修改紀錄讓覆蓋可回溯，還原不必重排。
## 後果／取捨
跨旅程查詢（如所有去過的國家）需額外彙整。刪除帳號或旅程時須確實清除相關足跡，含修改紀錄。沒填預計回程時間時，以結束日 23:59（當地時區）為準，時區要跟旅程一起保存。
