# 0007 隊長權限與修改審核
- 狀態：已採納（2026-10-26）｜關聯：#1
## 背景
團體要有人能拍板交通、回程與結束，但不能讓隊長卡住，也不能讓一般成員直接改掉大家的行程。
## 決策
1. 建立旅程者為隊長。2–4 人只有隊長，不設副隊長。5–7 人副隊長可選。8 人以上必須有正副隊長，沒有副隊長不能開始旅程。
2. 旅途中修改一般交通、回程交通，以及一般成員修改預計回程時間，都需正副隊長其中一位同意。以 Firestore 權限規則強制，不只靠 UI。一般成員送「修改申請」，推播給正副隊長；同意後才寫入。預計回程時間不能改成比現在早，App 擋下並提示。
3. 回程機票在開始時決定，之後修改需全員同意。這與「回程交通」（走散後回到團隊）不同。
4. 有副隊長，或 2–4 人團：修改申請 30 分鐘過期，逾期維持原設定並通知申請人。5–7 人且沒有副隊長的團：申請保留到隊長回應或指定副隊長回應，不設 30 分鐘過期。過期由 Cloud Function 排程處理。資料在 `trips/{tripId}/requests`，有時限的申請寫入 `expiresAt`。
5. 交接時隊長指定對象，對方可拒絕。連續兩次被拒後，由伺服器端隨機抽籤（輪盤抽籤）。所有成員參與，不含要離開的隊長；抽中者不能拒絕。過程存在 `handover`。
6. 隊長退出：2–3 人團解散；4 人團任一成員提出解散即解散；5 人以上必須先交接才能退出。
7. 換景點時若想單獨行動，要報備：填預計回來時間，推播全團，不需同意。未成年者需正副隊長其中一位同意。報備存在 `soloNotices`。註冊時填生日，一律以 18 歲判斷是否未成年——這是刻意簡化，不跟各國或美國各州規定（例如阿拉巴馬 19 歲、密西西比 21 歲）。生日屬個資，存在使用者帳號；其他成員只看得到「是否未成年」。
8. 結束旅程任何人都能按。一般成員按下只存成個人回憶（個人結束），團隊仍找得到他，位置分享照常。正副隊長按下才整團結束並清除位置。
## 理由
交通與預計回程時間影響全團，改動要有人點頭，但不必等所有人。Firestore 規則避免只藏按鈕仍能直接寫入。小團隊長可能忙，30 分鐘不過期會把行程卡住；沒有副隊長的 5–7 人團則不能讓申請默默失效。交接被連拒時用伺服器抽籤，避免隊長走不掉。未成年單獨行動多一道同意，生日本身不進旅程資料。
## 後果／取捨
權限規則要與 UI 一起維護。5 人以上隊長不能直接退出。輪盤抽籤不含要離開的隊長，抽中者沒有拒絕權。18 歲一刀切會與部分地區的成年年齡不同。個人結束後人還在找人地圖上，整團位置只在正副隊長結束或到預計回程時間時清除。
