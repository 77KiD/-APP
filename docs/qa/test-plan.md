# 第一版測試計畫（Test Plan V1）

對應規格：#1；票：#3–#12、#14、#15、#21、#25。原則：只測外部行為，驗收條件都要能實際驗證（見 #1「測試決策」）。

## 1. 測試層級與接縫

| 層級 | 範圍 | 工具 |
|---|---|---|
| 單元／規則測試 | 投票計分、排除、替代、排名、備選清單（純函式） | Dart `test` |
| 接縫一：Trip repository | 建立旅程、加入、投票、發送定位、結束旅程 | Firestore 模擬器 |
| 安全規則測試 | 非成員、旅程結束後的讀取權限；一般成員不得直接改回程時間、旅途中交通、回程交通、回程機票（#14） | `@firebase/rules-unit-testing` |
| 接縫二：排路線函式 | 輸入候選景點、交通時間矩陣、營業時間、每日時數，驗證輸出 | Cloud Functions 單元測試，Google API 一律用假資料 |
| Widget／整合測試 | 地圖標記、聚合、舊位置樣式、提示 | Flutter `integration_test` |
| 實機與實地測試 | 推播、省電模式、台日美戶外定位與路線 | 實機清單見第 4 節 |

每張票合併前：該票的自動化測試通過、CI 綠燈，且該票的離線案例通過。

## 2. 各票測試案例

### #3 專案骨架、旅程基礎、離線快取
旅程有「公開邀請」開關，預設開啟，只有隊長或副隊長能切換。開啟時任何成員都能產生邀請碼；關閉時只有隊長或副隊長能產生。每組碼自建立起 1 小時內有效，期間不限加入人數。多組碼可同時有效、各自獨立，新產生的碼不會使其他碼失效。關閉開關會立刻使一般成員產生、尚未過期的碼失效；隊長或副隊長產生的碼維持到該小時結束。到期與開關狀態都在伺服器以伺服器時間強制執行。

| ID | 情境 | 預期 |
|---|---|---|
| T3-1 | 登入後建立旅程 | 產生旅程與邀請 |
| T3-2 | 另一使用者用邀請加入 | 成為成員，看得到旅程 |
| T3-3 | 非成員直接讀取旅程文件 | 安全規則拒絕 |
| T3-4 | 使用無效的邀請碼 | 無法加入，有明確提示 |

### #21 線上模式：即時同步、在線狀態與群組通訊
對應 #21，以及 #15 的在線狀態、檢舉封鎖、內容政策與刪除帳號揭露。每一則都寫成可判定通過或失敗的步驟。層級只用 `client`、`rules`、`functions`、`manual device`。

有網路時，投票與行程修改走 Firestore listener 即時更新，不用手動重新整理。連線橫幅只有「線上」「離線中」「同步中」。離線修改標成「待上傳」，恢復連線後自動送出；衝突要讓使用者看得到，勝負仍沿用 #12，不另訂合併規則。

在線只算 App 在前景。退到背景、鎖螢幕、斷網、關掉 App 都算離線，並顯示最後上線時間。在線狀態不帶位置。每人可關閉自己的在線顯示。狀態寫在 RTDB `presence/{tripId}/{uid}`（ADR 0009），欄位只有 `online` 與 `lastSeen`（伺服器時間），用 `onDisconnect` 在斷線時改為離線。

聊天室在 `trips/{tripId}/messages`，只有隊員能讀寫，時間由伺服器寫入。第一版有文字、圖片與景點分享，語音之後再加。圖片放在 Cloud Storage `trips/{tripId}/chat/`，只有隊員能讀，聊天到期時與訊息一併刪除；刪除帳號後圖片與文字一樣留到 `chatExpiresAt`。景點分享只帶 place ID，不含座標。離線打的訊息（含圖片與景點分享）先排隊，連線後送出，順序以伺服器時間為準。送出者若已被移出，伺服器拒絕排隊中的訊息。不在聊天畫面的隊員收到 FCM。檢舉、封鎖與內容政策都要有；最低使用年齡 13 歲。

旅程結束時寫入 `chatExpiresAt`（該刻伺服器時間加 6 個月）。到期前 30 天與 7 天各提醒一次備份。備份是每人在聊天室按「匯出紀錄」，經 Android 分享表把檔案存到自己的手機；伺服器不因備份而延長期限，到期一律刪除。聊天室上方顯示刪除日期。刪除帳號不會立刻清掉規劃期與旅途中的訊息（T15-2 的直接刪除不含這些訊息）：訊息留到 `chatExpiresAt`，寄件者顯示「已刪除的成員」，且不再連到原帳號。刪除帳號畫面與隱私權政策都要寫明這一點。在線圓點與聊天須有 TalkBack 標籤，在線狀態不能只靠顏色。

排程類測試把伺服器時間撥到指定點再執行函式，不等真實的六個月。

自訂狀態每個旅程各存一份，只有本人能改，伺服器規則擋掉其他人。選項是自動（前景才算在線）、忙碌、勿擾（不收聊天推播）、隱身（其他人看到離線，且沒有最後上線時間）。最後上線時間可以另外單獨隱藏。狀態文字最多 30 字，只有同旅程隊員看得到，可以檢舉；檢舉由開發團隊在 24 小時內回應。可以設 30 分鐘、1 小時、今天結束或旅程結束時清回自動。設定對全隊生效，不能只對部分隊友隱藏，而且只影響聊天與在線，不影響定位或其他功能。隱身只能在旅途期間以外（規劃期，以及旅程結束後）使用；旅途中（開始日到旅程結束）規則拒絕隱身，未成年與成年相同。進入旅途時，排程把規劃期設下的隱身改回自動，並推播「旅程已開始，隱身已關閉」；旅程結束後不會自動變回隱身。

### #25 行程寫入：備選清單與修改紀錄
客戶端只寫 `trips/{tripId}/itinerary/{dayId}`，而且只送有變動的欄位，不可把沒改到的 `backupStops` 清成空陣列。`itineraryHistory` 只由 `onDocumentWritten` Cloud Function 寫；成員可讀，客戶端建立、更新、刪除都拒絕。較新的 `clientSavedAt` 勝出。被正常換掉的上一版記 `superseded`。比較晚上傳、但 `clientSavedAt` 較早的那筆記 `lost`，伺服器把較新版本寫回並標 `serverRestored`。規則層不拒絕較早的 `clientSavedAt`（這個做法已放棄）。還原寫入與同一個 event 的重送都不得再添一筆歷史。

| ID | 層級 | 前置 | 步驟 | 預期 |
|---|---|---|---|---|
| T25-1 | client | 該天已有 stops，且 backupStops 不是空的 | 只改 stops，寫入 `itinerary/{dayId}` | 寫入只含變動欄位；backupStops 與寫入前相同，沒有被清空 |
| T25-2 | rules | 成員已登入 | 客戶端建立、更新、刪除 `itineraryHistory` | 三項都拒絕 |
| T25-3 | rules | 已有一筆修改紀錄 | 成員與非成員分別讀取 | 成員可讀；非成員拒絕 |
| T25-4 | rules | 行程上已有較新的 clientSavedAt | 客戶端再寫入較早的 clientSavedAt | 規則接受，不在規則層拒絕，Function 才看得到這次寫入 |
| T25-5 | functions | A、B 離線改同一天。A 的 clientSavedAt 較早，B 較晚，而且 B 的 backupStops 有資料 | A 先上傳，B 再上傳 | 行程留下 B，含 B 的 backupStops；A 的版本在歷史，outcome 為 `superseded` |
| T25-6 | functions | 行程已是較新的 clientSavedAt，且 backupStops 有資料 | 之後才上傳較早儲存、backupStops 為空的版本 | 該筆記為 `lost`；行程被寫回較新版本（含原來的 backupStops），並一度標上 `serverRestored`。這次還原不再產生第二筆歷史 |
| T25-7 | functions | 帶 `serverRestored: true` 的寫入 | Function 處理這次寫入 | 不新增歷史，只清掉 `serverRestored`。清掉標記的那次寫入也不新增歷史，沒有迴圈 |
| T25-8 | functions | 同一個 Cloud Event 會被送兩次，event.id 相同 | 模擬同一 event 重送，含還原那一次 | 歷史文件 id 是 event.id（`/` 換成 `_`）；重送後仍然只有一筆，沒有重複 |
| T25-9 | functions | 其他成員正監聽該天 | 寫入較早的 clientSavedAt，等 Function 還原 | 記錄監聽是否在還原前短暫看到較舊版本。還原結束後必須回到較新版本，不能停在舊的 |
| T25-10 | functions | 兩筆 clientSavedAt 相同、stops 不同 | 先寫入甲，再寫入乙 | 後送到的乙留下；甲記成 `superseded`，不是 `lost` |
| T25-11 | client | 畫面上已是較新的 clientSavedAt | 監聽收到較早的 clientSavedAt | 畫面維持較新版本，直到還原寫入到達才換成還原後的內容 |
| T25-12 | client | 同 T25-11，但 Function 失敗，還原一直沒來 | 等待 | 不能一直停住。逾時後改顯示伺服器現況，並標明還原沒有完成。本測試以 5 秒為上限 |
| T25-13 | client | 歷史裡最新一筆 outcome 為 `lost` 的 recordedBy 是 A；B 是其他成員。另有一筆 `superseded` 屬於 C | A、B、C 都打開該天 | 只有 A 看到「你的離線修改比較舊」；B 與 C 看不到 |

## 3. 隱私與權限必測（跨票）
- 非成員讀不到旅程、投票、位置（#3、#10）。
- App 不申請背景定位（#8）。
- 正副隊長結束整團後，位置完全不可見，包括伺服器與本機快取（#10、#14）。一般成員自行結束只存個人回憶，團隊仍找得到他。

## 4. 實機與實地測試
- 品牌與省電模式：小米、OPPO、三星，各開啟省電模式測推播送達（#12）。
- Android 版本：至少涵蓋三個主要版本（實際版本待依目標使用者定案）。
- 實地：台灣、日本、美國戶外各測定位準確度與回程路線（#8、#11）。
